DOCUMENTACION DESCRIPTIVA DEL BACKEND - UNIAVISOS
================================================

1. PROPOSITO Y ALCANCE
----------------------
El backend de UniAvisos ofrece una API HTTP para administrar usuarios,
categorias y anuncios institucionales. Tambien permite autenticar usuarios
mediante tokens Bearer y cargar imagenes o documentos PDF a Supabase Storage.

Esta descripcion se basa en los archivos actualmente versionados bajo
backend/app y en backend/requirements.txt. No describe funcionalidades que no
esten implementadas en esos archivos.


2. TECNOLOGIAS Y COMPONENTES
----------------------------
- Python y FastAPI: definicion de la API, rutas, validacion de entrada y
  documentacion OpenAPI automatica.
- SQLAlchemy: modelos relacionales, consultas y sesiones de base de datos.
- PostgreSQL: dialecto esperado por los tipos UUID de los modelos.
- psycopg y psycopg-binary: conector de PostgreSQL.
- Pydantic: validacion y serializacion de datos de las solicitudes y
  respuestas.
- PyJWT: creacion y validacion de tokens de acceso.
- argon2-cffi: hash y verificacion de contrasenas.
- python-dotenv: lectura de variables desde un archivo .env.
- httpx: comunicacion con el servicio de almacenamiento de Supabase.
- Uvicorn: servidor ASGI utilizado habitualmente para ejecutar FastAPI.

Las versiones instaladas/declaradas se encuentran fijadas en
backend/requirements.txt. Entre las dependencias principales se encuentran
FastAPI 0.162.0, SQLAlchemy 2.1.6, Pydantic 2.14.2, PyJWT 2.15.1,
argon2-cffi 25.1.0, psycopg 3.3.6 y Uvicorn 0.54.0.


3. ESTRUCTURA DEL CODIGO
------------------------
backend/app/main.py
    Crea la aplicacion FastAPI, configura CORS, crea las tablas declaradas
    por los modelos al iniciar y registra los routers.

backend/app/config/settings.py
    Carga variables del entorno y comprueba la presencia de DATABASE_URL.

backend/app/config/database.py
    Crea el engine de SQLAlchemy, la fabrica de sesiones y la dependencia
    get_db usada por las rutas.

backend/app/models/
    Define las entidades Usuario, Categoria y Anuncio y sus relaciones.

backend/app/schemas/
    Define los formatos y validaciones de los datos de entrada y salida.

backend/app/routers/
    Implementa las rutas HTTP de autenticacion, usuarios, categorias,
    anuncios y archivos.

backend/app/services/
    Contiene funciones para autenticacion/autorizacion, hash de contrasenas
    y carga de archivos.

backend/.env.example
    Presenta los nombres de las variables de entorno requeridas o utilizadas.
    Debe completarse localmente con valores validos; no se deben publicar
    claves reales.


4. INICIO DE LA APLICACION Y CONFIGURACION
------------------------------------------
La aplicacion FastAPI se instancia con el titulo "UniAvisos API". La
configuracion CORS permite solicitudes desde:
- http://localhost:3000
- http://localhost:5173

Los metodos y encabezados HTTP estan permitidos de forma amplia para esos
origenes. No se configura explicitamente allow_credentials.

Al importar app.main se ejecuta Base.metadata.create_all(bind=engine). Esto
crea las tablas declaradas si no existen, pero no es un sistema de migraciones
ni modifica automaticamente una estructura existente para reflejar cambios
posteriores en los modelos.

Variables de entorno:
- DATABASE_URL: cadena de conexion a PostgreSQL. Es obligatoria; la aplicacion
  falla al inicializar la configuracion si falta.
- SECRET_KEY: clave usada para firmar tokens JWT. Es obligatoria para el
  servicio de autenticacion.
- ACCESS_TOKEN_EXPIRE_MINUTES: duracion del token en minutos; su valor por
  defecto en el codigo es 60.
- SUPABASE_URL: URL base del proyecto de Supabase usada para almacenamiento.
- SUPABASE_SERVICE_KEY: clave de servicio utilizada para las solicitudes al
  almacenamiento.
- SUPABASE_BUCKET: bucket utilizado para guardar archivos; por defecto es
  "anuncios".

La conexion a la base de datos se crea con pool_pre_ping habilitado. Cada
solicitud que usa get_db obtiene una sesion y esta se cierra al finalizar.


5. MODELO DE DATOS
------------------

5.1 Usuario (tabla usuarios)
- id: UUID, clave primaria, generado por la aplicacion.
- nombre: texto obligatorio, hasta 150 caracteres.
- correo: texto obligatorio y unico, hasta 150 caracteres.
- password_hash: hash de contrasena obligatorio, hasta 255 caracteres.
- rol: texto obligatorio; por defecto "estudiante".
- facultad: texto opcional, hasta 150 caracteres.
- carrera: texto opcional, hasta 150 caracteres.
- creado_en: fecha/hora con zona horaria, asignada por la base de datos.
- Relacion: un usuario puede estar asociado a varios anuncios.

Los roles contemplados por las validaciones son estudiante, publicador y
administrador. El registro publico crea siempre usuarios con rol estudiante.

5.2 Categoria (tabla categorias)
- id: UUID, clave primaria, generado por la aplicacion.
- nombre: texto obligatorio, hasta 100 caracteres.
- descripcion: texto opcional.
- creado_en: fecha/hora con zona horaria, asignada por la base de datos.
- Relacion: una categoria puede tener varios anuncios.

5.3 Anuncio (tabla anuncios)
- id: UUID, clave primaria, generado por la aplicacion.
- titulo: texto obligatorio, hasta 200 caracteres.
- resumen: texto opcional.
- contenido: texto obligatorio.
- categoria_id: UUID obligatorio, referencia a categorias.id.
- usuario_id: UUID obligatorio, referencia a usuarios.id.
- facultad y carrera: textos opcionales de hasta 150 caracteres.
- importancia: texto con valor predeterminado "normal"; la API valida los
  valores "normal", "importante" y "urgente".
- imagen_url y archivo_url: URL/texto opcional para recursos asociados.
- fecha_publicacion: fecha/hora con zona horaria; por defecto la base de datos
  asigna la hora actual.
- fecha_vencimiento: fecha/hora con zona horaria opcional.
- creado_en: fecha/hora con zona horaria, asignada por la base de datos.
- Relaciones: cada anuncio pertenece a un usuario y a una categoria.


6. AUTENTICACION Y AUTORIZACION
-------------------------------
El inicio de sesion recibe un formulario OAuth2 con los campos username y
password. En este backend, username corresponde al correo del usuario. Si las
credenciales son correctas, se devuelve access_token y token_type "bearer".

La contrasena se guarda como hash Argon2. El token JWT se firma con HS256,
contiene el UUID del usuario en el campo sub y una fecha de expiracion exp.
Las rutas protegidas esperan el token mediante el encabezado:

    Authorization: Bearer <access_token>

El endpoint /api/auth/me devuelve los datos publicos del usuario autenticado.
Las respuestas de usuario no incluyen password_hash.

Permisos principales:
- Estudiante: puede consultar datos publicos, pero no publicar ni administrar
  contenido. Puede consultar y actualizar su propio perfil.
- Publicador: puede crear anuncios, modificar o eliminar sus propios anuncios
  y cargar imagenes/PDF.
- Administrador: puede gestionar usuarios y categorias, cambiar roles y
  administrar cualquier anuncio.

Una persona que no sea administradora solo puede acceder al detalle o
actualizacion de su propio usuario. Publicadores y administradores pueden
gestionar anuncios, pero el publicador solo puede modificar/eliminar anuncios
de su propiedad. Los endpoints de listado de usuarios y cambio de roles son
exclusivos para administradores.

La aplicacion distingue errores de autenticacion (HTTP 401) y falta de
permisos (HTTP 403).


7. ENDPOINTS HTTP
-----------------
Las rutas indicadas usan el prefijo /api salvo la ruta raiz y la comprobacion
de base de datos. FastAPI genera tambien los endpoints habituales de
documentacion OpenAPI, como /docs y /openapi.json.

7.1 General
- GET /
  Publico. Devuelve un mensaje que indica que UniAvisos API esta funcionando.
- GET /api/health/db
  Ejecuta SELECT 1 usando la base de datos y devuelve el estado de conexion.
  La respuesta menciona Supabase, aunque la comprobacion efectiva es una
  consulta a la base de datos configurada en DATABASE_URL.

7.2 Autenticacion (/api/auth)
- POST /api/auth/login
  Publico. Recibe formulario username/correo y password. Devuelve token
  Bearer si las credenciales son validas; credenciales invalidas producen
  HTTP 401.
- GET /api/auth/me
  Requiere token valido. Devuelve el perfil del usuario autenticado.

7.3 Usuarios (/api/usuarios)
- POST /api/usuarios
  Publico. Registra un estudiante. Valida nombre de 2 a 150 caracteres,
  correo con formato de email y contrasena de 8 a 72 caracteres. Facultad y
  carrera son opcionales. Un correo ya registrado produce HTTP 409.
- GET /api/usuarios
  Solo administrador. Devuelve todos los usuarios ordenados por nombre.
- GET /api/usuarios/{usuario_id}
  Requiere autenticacion; solo el propio usuario o un administrador pueden
  consultar el detalle.
- PUT /api/usuarios/{usuario_id}
  Requiere autenticacion; solo el propio usuario o un administrador pueden
  actualizar nombre, facultad o carrera. El esquema no permite cambiar aqui
  correo, contrasena ni rol.
- PUT /api/usuarios/{usuario_id}/rol
  Solo administrador. Cambia el rol a estudiante, publicador o administrador.

7.4 Categorias (/api/categorias)
- GET /api/categorias
  Publico. Lista categorias ordenadas por nombre.
- GET /api/categorias/{categoria_id}
  Publico. Devuelve una categoria o HTTP 404 si no existe.
- POST /api/categorias
  Solo administrador. Crea una categoria; nombre debe tener entre 2 y 100
  caracteres y descripcion es opcional.
- PUT /api/categorias/{categoria_id}
  Solo administrador. Actualiza nombre o descripcion.
- DELETE /api/categorias/{categoria_id}
  Solo administrador. Elimina una categoria si no tiene anuncios asociados.
  Si tiene anuncios, devuelve HTTP 409.

7.5 Anuncios (/api/anuncios)
- GET /api/anuncios
  Publico. Lista anuncios con filtros opcionales:
    q: busqueda parcial, sin distincion entre mayusculas/minusculas, en titulo.
    categoria_id: UUID de categoria.
    facultad: coincidencia exacta.
    carrera: coincidencia exacta.
    importancia: normal, importante o urgente.
    solo_vigentes: por defecto true.
    skip: cantidad de registros a omitir; minimo 0.
    limit: cantidad maxima; por defecto 20, minimo 1 y maximo 100.
  Cuando solo_vigentes es true, incluye anuncios cuya fecha_publicacion ya
  llego y que no tienen fecha_vencimiento o cuya fecha_vencimiento aun no
  llego. Ordena por fecha_publicacion descendente.
- GET /api/anuncios/{anuncio_id}
  Publico. Devuelve el anuncio o HTTP 404 si no existe.
- POST /api/anuncios
  Requiere rol publicador o administrador. El usuario autenticado queda
  asociado como autor. La categoria debe existir. Valida titulo de 3 a 200
  caracteres, contenido no vacio e importancia dentro de los valores
  permitidos. El resto de campos opcionales incluye resumen, facultad,
  carrera, URLs de recursos y fechas.
- PUT /api/anuncios/{anuncio_id}
  Requiere rol publicador o administrador. Solo el autor o un administrador
  puede actualizarlo. Si se cambia la categoria, esta debe existir.
- DELETE /api/anuncios/{anuncio_id}
  Requiere rol publicador o administrador. Solo el autor o un administrador
  puede eliminarlo.

7.6 Archivos (/api/archivos)
- POST /api/archivos/imagen
  Requiere rol publicador o administrador. Recibe el archivo como multipart
  bajo el campo "archivo". Acepta JPEG, PNG y WebP, hasta 5 MB.
- POST /api/archivos/pdf
  Requiere rol publicador o administrador. Recibe el archivo como multipart
  bajo el campo "archivo". Acepta PDF hasta 10 MB.

La validacion de archivos comprueba tanto el MIME declarado como la firma
inicial del contenido. Se genera un nombre aleatorio y se carga en Supabase
Storage bajo la carpeta "imagenes" o "documentos" del bucket configurado. La
respuesta exitosa contiene la URL publica del objeto. Si falta la
configuracion de almacenamiento se devuelve HTTP 500; tipos no permitidos,
archivos demasiado grandes o firmas incorrectas producen HTTP 415, HTTP 413 o
HTTP 400, respectivamente. Un fallo del servicio remoto se devuelve como
HTTP 502.


8. CODIGOS DE RESPUESTA Y VALIDACION
------------------------------------
FastAPI/Pydantic valida los UUID, tipos y restricciones declaradas en los
esquemas. Ademas de respuestas exitosas, las rutas usan principalmente:
- HTTP 400: contenido de archivo incompatible con el MIME.
- HTTP 401: credenciales incorrectas o token invalido/expirado.
- HTTP 403: rol o propiedad insuficiente.
- HTTP 404: usuario, categoria, anuncio o categoria relacionada inexistente.
- HTTP 409: correo duplicado o categoria que todavia tiene anuncios.
- HTTP 413: archivo por encima del limite de tamano.
- HTTP 415: tipo de archivo no permitido.
- HTTP 422: datos de solicitud que no cumplen validaciones de FastAPI/Pydantic.
- HTTP 500: configuracion de almacenamiento ausente.
- HTTP 502: error al guardar un archivo en el servicio remoto.


9. EJECUCION LOCAL
------------------
Desde la carpeta backend, crear un entorno virtual, instalar las dependencias
de requirements.txt y configurar las variables anteriores en un archivo
.env. Luego se puede iniciar el servidor ASGI con:

    uvicorn app.main:app --reload

La disponibilidad de la API requiere una DATABASE_URL valida y una base de
datos PostgreSQL accesible. Las funciones de autenticacion requieren
SECRET_KEY. Las cargas de archivos requieren SUPABASE_URL y
SUPABASE_SERVICE_KEY.


10. ALCANCES Y LIMITES OBSERVABLES
----------------------------------
- El codigo configura CORS para los dos origenes locales indicados; no lista
  otros origenes de frontend.
- El listado de usuarios no incorpora paginacion en el router.
- El listado de anuncios si incorpora paginacion basica mediante skip y
  limit.
- No se observan en los archivos revisados rutas para recuperar contrasena,
  cambiar contrasena, borrar una cuenta, moderar anuncios ni gestionar
  permisos personalizados.
- Las migraciones de esquema no estan descritas por la estructura revisada;
  el inicio usa create_all de SQLAlchemy.
- La configuracion de produccion (dominios CORS, almacenamiento, base de
  datos y claves) depende de variables y valores del entorno.
